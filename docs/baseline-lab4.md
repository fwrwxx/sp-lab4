# Базова лінія для ЛР4

## Сценарії (відтворення 1-в-1)

- **S1 (простій)**: старт → нічого не робити 30 с → `STATS`.
- **S2 (номінальний)**: `RESET` → 60 с без натискань → `STATS`.
- **S3 (найгірший)**: `RESET` → `LONG` × 5 з інтервалом 1 с, паралельно натискати кнопку 30+ разів → `STATS`.
- **W1 (відмова IMU)**: відключити `imu1` у Wokwi → `STATS` через 10 с.
- **W2 (потік UART)**: надіслати 100 команд поспіль → перевірити `cmd_overflow`.

## Гіпотези для ЛР4 (перевірити з FreeRTOS)

| # | Гіпотеза | Очікувана метрика |
|---|---|---|
| 1 | Пріоритет IMU > flash → IMU не блокується `long_op` | `imu_jitter_max` < 1 000 мкс у S3 (зараз 84 826) |
| 2 | Пріоритет button > flash → кнопка реагує швидко | `btn_latency_max` < 100 мкс (зараз 80 000+) |
| 3 | Черга UART ISR → задача → `uart_cmd.max` малий | `uart_cmd.max_us` < 100 (зараз 81 360) |
| 4 | `vTaskDelayUntil` для IMU → стабільний період | `imu_jitter_max` < 200 мкс у S1 |
| 5 | Стеки задач: 5 × 512 B = 2.5 КБ RAM, разом RAM ≈ 5.2 КБ (42%) | RAM < 60% |
| 6 | Старт FreeRTOS додасть ~5 мс до `APP init` | час старту < 50 мс |

## Інструментарій (без змін у ЛР4)

- Команда `STATS` у UART → `docs/metrics/*.log`.
- `tools/analyze_log.py`.
- Logic Analyzer: PROBE_IMU (PA8), PROBE_LONG (PA9), PROBE_BTN (PA10), EXTI (PC13).
- `STACK` через `stack_paint` → глибина стека головної задачі.
- У ЛР4 додати `uxTaskGetStackHighWaterMark()` для кожного стека.
